# 自选文档站规格

## 目标

为“自选”提供一套与产品同仓维护、可直接浏览的中文文档，覆盖普通用户和开发者两类读者。文档必须在本地应用中可通过 `/docs/` 打开，并通过 GitHub Pages 发布；不依赖 OpenAI Sites 或其他托管服务。

## 信息架构

文档站为无构建依赖的静态站点，入口为 `docs/index.html`，包含以下区域：

1. 概览：产品定位、核心能力、当前边界。
2. 用户指南：快速开始、添加订阅、今日阅读、合集、发现、搜索、专注模式、数据与隐私、备份恢复、常见问题。
3. 开发者指南：本地开发、项目结构、前后端职责、数据模型、来源预览 API、安全边界、测试与发布。
4. 能力清单：明确区分“现已支持”和“暂未支持”，避免将演示或本地能力描述为云端能力。

每个主要章节必须有稳定的锚点，可由侧栏目录、页内链接和浏览器 URL 直接访问。

## 交互与可访问性

- 桌面端使用固定目录与正文双栏布局；移动端目录可折叠。
- 支持按标题、说明和关键词即时筛选文档章节；无结果时显示清晰反馈。
- 代码块提供复制按钮，并以可感知状态告知复制成功或失败。
- 支持键盘导航、跳转到正文、可见焦点、语义化标题和 `aria` 标签。
- 尊重 `prefers-reduced-motion`，不使用影响阅读的持续动画。
- 所有样式和脚本使用相对路径，保证 `/docs/` 与 GitHub Pages 项目子路径均可运行。

## 本地集成

- 源文件仅在 `docs/` 维护。
- `scripts/sync-docs.mjs` 在开发和构建前将文档同步到 `public/docs/`。
- `public/docs/` 是生成目录，不提交到版本库。
- 产品桌面侧栏和移动端导航提供“文档”入口，目标为 `/docs/`。

## GitHub Pages 发布

- `.github/workflows/docs-pages.yml` 在 `main` 分支的文档或工作流发生变化时发布，也支持手动触发。
- 工作流上传 `docs/` 作为 Pages artifact，并使用 GitHub 官方 Pages Actions 部署。
- 工作流只申请 `contents: read`、`pages: write` 与 `id-token: write` 权限，并使用 `github-pages` environment 和并发控制。
- 仓库 Pages 发布源需设置为 GitHub Actions。

## 兼容性与边界

- 文档站不要求 JavaScript 才能阅读；搜索、移动目录和复制按钮属于渐进增强。
- 文档描述当前产品真实行为：数据默认保存在浏览器本地；RSS 可获取预览；Bilibili 等受限制来源可用链接订阅；不宣称跨设备同步、账号系统或云端托管能力。
- 页面资源不得依赖外部 CDN，避免离线或网络策略导致基础文档不可用。

## 验收标准

- `docs/index.html`、本地 CSS/JS、`.nojekyll` 均存在。
- 用户指南和开发者指南覆盖上述主题，并包含项目结构、能力清单、存储键与预览 API。
- 应用内存在可访问的 `/docs/` 入口。
- 开发和构建命令自动同步文档，构建产物包含 `docs/index.html`。
- GitHub Pages 工作流使用当前官方 Actions，权限与发布目录正确。
- 文档专项测试、现有测试、构建和 lint 全部通过。
- GitHub Pages URL 可公开访问并返回文档首页。
