# 浏览器助手规格

## 目标

“自选助手”是随仓库交付的 Manifest V3 浏览器扩展。它在用户主动点击时读取当前页面的公开元数据，把单篇内容、来源候选或 Bilibili 关注页中当前可见的 UP 主送入“自选”本地应用。扩展不要求用户在“自选”中登录平台，不读取、保存或传输密码、Cookie、访问令牌，也不调用平台未公开接口。

## 用户能力

扩展弹窗在普通网页提供以下动作：

1. “稍后看”：保存规范 URL、标题、摘要、站点名、封面和用户当前选中的文字。
2. “收藏到合集”：捕获相同元数据，并在“自选”中由用户选择本地合集。
3. “订阅来源”：优先使用页面声明的 RSS/Atom 地址；没有公开 Feed 声明时提交当前规范页面，由现有 `/api/source-preview` 流程识别作者主页、平台账号、网站 Feed、RSSHub 或链接模式。

Bilibili 页面额外提供批量关注扫描：

1. 用户开始一轮扫描，扩展清空本轮临时候选，但保留上一次已完成快照。
2. 用户在自己的关注页滚动或切换分页后点击“扫描本页”；扩展只读取 DOM 中当前可见的 `space.bilibili.com/{mid}` 链接，并按 MID 合并去重。
3. 用户完成本轮扫描后，扩展计算相对上次快照的新增与不再出现账号，并把完整候选及差异送往“自选”。
4. “自选”默认勾选新增且尚未订阅的来源；已有来源跳过，不再出现的关注只提示，绝不自动暂停、归档或删除。

### Bilibili 自动全量扫描

- 用户必须主动打开自己的 `space.bilibili.com/{mid}/relation/follow` 全部关注页面并点击“自动扫描全部关注”；扩展不在后台访问账号，也不读取 Cookie 或调用未公开接口。
- 页面脚本从每张已渲染的关注卡片提取 MID、公开昵称、个人空间 URL 与公开头像 URL。重复 MID 合并时保留信息更完整的昵称和头像。
- 扫描器识别当前分页控件，按页面顺序逐页点击“下一页”，等待关注卡片集合发生变化后再采集；兼容同页更新和同源整页导航。同源整页导航后由 Service Worker 重新注入脚本并从本地扫描状态继续。
- 页面内显示扫描页数、累计账号数、暂停/取消入口与错误信息；扩展弹窗关闭不应中断同页扫描。用户取消、登录失效、验证码、连续重复页面、超过 200 页或 15 秒内页面内容未更新时停止，保留已收集候选供重试或手动发送。
- 到达最后一页后自动完成本轮、计算差异并发送到自选确认页；自动发送不等于自动订阅，用户仍需在应用中确认导入。

## 本地配对与通信

- 应用使用独立于备份数据的 `our-choice:assistant:v1` 本地存储保存随机配对码；配对码不进入 `AppData`、JSON 备份、URL、日志或页面正文。
- 用户在“设置 → 浏览器助手”生成配对码，并在扩展弹窗中保存本地应用地址与配对码。撤销后旧配对码立即失效。
- 收藏、订阅和“完成并发送”必须先有已保存的配对码；缺少配对码时扩展不创建队列、不结束当前关注扫描，并在弹窗中要求完成连接设置。
- 扩展只为 `http://localhost:3000/*` 与 `http://127.0.0.1:3000/*` 注入最小通信桥。页面通过 `window.postMessage` 请求队列；通信桥把配对码交给后台脚本校验后才返回数据或确认删除。
- 成功入队后扩展打开 `/#browser-assistant` 本地交接地址；该片段不包含配对码或队列数据。应用在初始化期间短暂重试拉取队列，以覆盖通信桥与页面代码的加载时序差异。
- 扩展队列保存在 `chrome.storage.local`。接收失败不会丢失数据；应用只确认已成功保存或判定为重复的队列项，失败项留待重试。
- 当前页面解析仅在用户点击扩展按钮后，以 `activeTab` 和 `scripting` 临时权限执行；Manifest 不申请 `cookies`、`webRequest`、`history` 或全站常驻读取权限。

## 数据映射

- 任意网页收藏映射为隐藏的系统来源“网页剪藏”下的一条 `article`、`video` 或 `podcast` 内容；隐藏来源不出现在订阅列表，也不进入“今日”，但内容可在稍后看、合集和搜索中出现。
- 同一规范 URL 已存在时不创建重复内容，只补充目标合集关系。
- 订阅候选必须经过 `/api/source-preview`，不得由扩展直接构造可自动刷新的 Feed。批量导入遇到多范围来源时，Bilibili 默认选择标题含“投稿”或“视频”的一个范围，其他平台选择第一个安全候选；用户之后可在来源设置中调整。
- 来源以规范化公开 URL 去重。批量加入时建立当前时间基线，预览到的历史条目不计入新增；批量导入默认不保留历史条目，避免污染“今日”。
- Bilibili 候选的公开昵称优先成为订阅源名称，公开头像 URL 写入来源的 `imageUrl`；应用使用圆角头像展示，图片不可用时回退到现有的名称首字色块。头像仅保存 URL，不下载图片二进制，也不进入扩展权限范围之外的请求。
- 捕获数据只包含公开页面元数据和用户主动选中的文字。第一版不保存完整正文或页面快照。

## 扩展界面

- 弹窗顶部显示当前页面标题、站点和识别状态。
- 未配置时显示本地应用地址与配对码输入；配置成功后仍允许修改。
- 普通捕获按钮在成功入队后打开或聚焦本地应用。
- Bilibili 扫描区显示本轮累计数量、本页新增数量、开始/重新开始、扫描本页和完成并发送操作。
- 全部关注页面额外提供“自动扫描全部关注”；运行中显示进度并允许取消，普通页面不显示或禁用该操作。
- “完成并发送”成功后明确提示仍需在应用确认导入；若配对未完成，扫描状态和本轮候选保持不变。
- 无法访问的页面（浏览器内部页、扩展页或没有公开 HTTP(S) URL）显示明确错误，不创建队列项。
- 提供“导出待处理 JSON”作为通信不可用时的恢复路径；导出不包含配对码。

## 应用界面

- “订阅”页提供“浏览器助手”入口；设置中提供安装路径、隐私说明、生成/复制/撤销配对码和“检查待处理内容”。
- 收到队列后打开确认弹窗，分为网页收藏和来源候选，默认勾选可导入且不重复的项目。
- 通过交接地址打开但本地配对码缺失、错误或扩展桥未响应时，应用自动打开浏览器助手设置并显示具体恢复提示，不允许静默停留在首页。
- 收藏区可统一选择“稍后看”或一个用户自建合集；来自“收藏到合集”的项目必须选择合集才能确认。
- 来源区显示平台、名称、URL、已订阅状态和 Bilibili 关注差异摘要。
- 导入期间限制为最多三路来源预览并显示处理状态；完成后汇报收藏数、订阅数、重复数和失败数。

## 文件与兼容性

- 扩展源码位于 `browser-extension/`，不需要构建即可通过 Chromium 的“加载已解压的扩展程序”安装。
- Service Worker 与临时页面注入共享的辅助脚本必须使用标准 `.js` 扩展名；不得通过 `importScripts()` 加载 `.cjs`，因为 Chromium 会把扩展内 `.cjs` 作为 `application/octet-stream` 并拒绝注册 Service Worker。
- 首版目标为 Chrome/Edge Manifest V3；页面解析和数据契约保持浏览器 API 之外的纯函数，供 Node 测试验证。
- 应用仍可在没有扩展时独立运行，现有备份格式和 `our-choice:state:v1` 数据保持向后兼容。

## 验收标准

- Manifest 仅声明 `activeTab`、`scripting`、`storage`，通信桥只匹配两个本地应用来源。
- 扩展目录不包含被 Service Worker 引用的 `.cjs` 文件；`background.js` 和页面注入统一加载 `shared.js`，保证“加载已解压的扩展程序”可完成注册。
- 页面解析可以提取规范 URL、RSS/Atom、选中文字和 Bilibili MID，并过滤非 HTTP(S) 与重复候选。
- Bilibili 卡片解析可以提取并合并 MID、昵称与头像；订阅列表和来源详情显示头像并具备首字回退。
- 关注扫描可以合并多次本页结果并计算新增/不再出现差异；空扫描不能覆盖上一次完成快照。
- 自动全量扫描覆盖分页推进、同源导航恢复、重复页终止、超时/取消保留结果、末页自动发送，以及最多 200 页保护上限。
- 应用可以接收、校验、预览和确认收藏、单来源订阅及 Bilibili 批量来源；重复项不重复创建。
- 未配对时发送操作保持扩展队列与关注扫描不变；已配对交接会自动打开确认弹窗，失败时必须显示可操作的配对或连接错误。
- 配对码与扩展队列不进入应用 JSON 备份，撤销配对后无法拉取队列。
- 新增专项测试、现有测试、构建与 lint 全部通过；本地浏览器验证覆盖生成配对码、打开助手确认界面和保存捕获内容。
