# 浏览器助手规格

## 目标

“自选助手”是随仓库交付的 Manifest V3 浏览器扩展。它在用户主动点击时读取当前页面的公开元数据，把单篇内容、来源候选或 Bilibili 关注页中当前可见的 UP 主送入“自选”本地应用。扩展不要求用户在“自选”中登录平台，不读取、保存或传输密码、Cookie、访问令牌，也不调用平台未公开接口。

## 用户能力

扩展弹窗在普通网页提供以下动作：

1. “稍后看”：保存规范 URL、标题、摘要、站点名、封面和用户当前选中的文字。
2. “收藏到合集”：捕获相同元数据，并在“自选”中由用户选择本地合集。
3. “订阅来源”：优先使用页面声明的 RSS/Atom 地址；没有公开 Feed 声明时提交当前规范页面，由现有 `/api/source-preview` 流程识别作者主页、平台账号、网站 Feed、RSSHub 或链接模式。

Bilibili 页面额外提供批量关注扫描：

1. 用户开始一轮扫描，扩展清空本轮临时候选，但保留上一次已完成快照。
2. 用户在自己的关注页滚动或切换分页后点击“扫描本页”；扩展只读取 DOM 中当前可见的 `space.bilibili.com/{mid}` 链接，并按 MID 合并去重。
3. 用户完成本轮扫描后，扩展计算相对上次快照的新增与不再出现账号，并把完整候选及差异送往“自选”。
4. “自选”默认勾选新增且尚未订阅的来源；已有来源跳过，不再出现的关注只提示，绝不自动暂停、归档或删除。

### Bilibili 自动全量扫描

- 用户必须主动打开自己的 `space.bilibili.com/{mid}/relation/follow` 全部关注页面并点击“自动扫描全部关注”；扩展不在后台访问账号，也不读取 Cookie 或调用未公开接口。
- 页面脚本从每张已渲染的关注卡片提取 MID、公开昵称、个人空间 URL 与公开头像 URL。重复 MID 合并时保留信息更完整的昵称和头像。
- 扫描器识别当前分页控件，按页面顺序逐页点击“下一页”，等待关注卡片集合发生变化后再采集；兼容同页更新和同源整页导航。同源整页导航后由 Service Worker 重新注入脚本并从本地扫描状态继续。
- 页面内显示扫描页数、累计账号数、暂停/取消入口与错误信息；扩展弹窗关闭不应中断同页扫描。用户取消、登录失效、验证码、连续重复页面、超过 200 页或 15 秒内页面内容未更新时停止，保留已收集候选供重试或手动发送。
- 到达最后一页后自动完成本轮、计算差异并发送到自选确认页；自动发送不等于自动订阅，用户仍需在应用中确认导入。
- 单个 `follow-batch` 的候选上限为 500。当本轮去重后超过 500 个账号时，“完成并发送”必须在任何桌面请求、本地入队或快照替换前明确失败，不得生成永远无法被桌面端接受的 poison queue。失败后本轮 `active/current/previous` 保持不变，由用户重新分批扫描。

## 本地配对与通信

- 安装版 Mac App 默认自动连接：每次内置 Node 进程启动生成一个不持久化的高熵扩展会话，扩展在自动发现端口时从健康端点取得它，无需用户生成、复制或保存配对码。应用重启后旧会话失效，扩展收到 401 时重新发现并透明续连一次。
- Docker 与普通浏览器网页模式没有原生会话，继续使用独立于备份数据的 `our-choice:assistant:v1` 本地存储保存随机配对码；用户可在“设置 → 浏览器助手”生成配对码并在扩展高级连接设置中保存。配对码不进入 `AppData`、JSON 备份、URL、日志或页面正文，撤销后立即失效。
- Mac 宿主每次启动生成一个不持久化的原生 bootstrap secret，只通过最小子进程环境传给内置 Node，并以 main-frame-only 的 `WKUserScript` 注入宿主 WKWebView。`POST /__our_choice/assistant/pair` 的登记和撤销都必须同时携带该 secret；仅凭 `localhost`/`127.0.0.1` Origin 不足以修改桌面配对。因此用普通 Chrome/Safari 打开同一网站时，空的或过期的 Web `localStorage` 不能覆盖、更换或撤销原生应用配对。secret 不进入磁盘、URL、ready 消息或日志。
- 收藏、订阅和“完成并发送”必须先取得短期原生会话或已保存的网页模式配对码；两者都没有时扩展不创建队列、不结束当前关注扫描，并在弹窗中提示打开 Mac App 或配置网页模式配对码。
- 扩展先验证已记住的 loopback 地址，再并行探测 `http://127.0.0.1:3000` 至 `http://127.0.0.1:3031` 的健康端点；探测固定发送 `x-our-choice-extension-session: request`，兼容扩展后台 GET 省略 Origin 的 Chrome/Safari 版本。只有 HTTP 成功且 `product` 精确为 `our-choice-desktop` 才更新配置，伪装的其他本地服务不能被当作应用。有效扩展探测响应可携带长度受限的短期会话；无标记请求或带普通 HTTP Origin 的请求不得包含该字段，普通网页的跨域 OPTIONS 不得获准发送该请求头。发现结果通过既有串行配置事务保存，不能覆盖并发保存的新网页配对码或标签 ID。扩展为 `http://localhost/*` 与 `http://127.0.0.1/*` 注入最小通信桥，使自动端口上的交接页面可用；页面仍须通过 `window.postMessage` 和网页配对码鉴权请求扩展降级队列，短期原生会话不得转发给页面。
- 成功入队后扩展打开 `/#browser-assistant` 本地交接地址；该片段不包含配对码或队列数据。应用在初始化期间短暂重试拉取队列，以覆盖通信桥与页面代码的加载时序差异。
- Web 页面走扩展本地队列降级通道时，ACK 请求必须生成唯一 `requestId`，并等待同源通信桥返回同一 `requestId` 的 `OUR_CHOICE_ACK_RESPONSE`。只有回复中 `ok=true` 才能从页面待处理列表移除对应项；错误回复、错误的 `requestId` 或 1.8 秒内无回复都必须按确认失败处理并保留队列。Chrome 与 Safari adapter 继续共用这一消息契约。
- 扩展队列保存在 `chrome.storage.local`。入队、ACK 与投递后删除必须共用一个串行化的 read-modify-write 边界；投递后必须重新读取当前队列并只删除已确认 ID，不得用投递前的快照覆盖并发新入队。队列最多保留 500 项；已满时新入队必须明确失败并保留全部旧项，不得通过截断静默淘汰未处理数据。接收失败不会丢失数据；应用只确认已成功保存或判定为重复的队列项，失败项留待重试。
- 当前页面解析仅在用户点击扩展按钮后，以 `activeTab` 和 `scripting` 临时权限执行；Manifest 不申请 `cookies`、`webRequest`、`history` 或全站常驻读取权限。

### 桌面队列的服务端边界

`POST /__our_choice/assistant/enqueue` 不信任扩展或其他调用方已经做过清洗。服务端必须在写入 `assistant-state.json` 前验证数据，并逐字段构造一个新的队列对象；不得返回或持久化调用方原对象。具体规则如下：

- 公共字段只允许 `id`、`kind` 和 `capturedAt`。`id` 去掉首尾空白后必须为 1–160 个字符；`capturedAt` 必须是可解析的日期时间字符串，服务端将其重建为 ISO 8601 UTC 形式。
- `clip` 只保留 `destination` 及 `page.url/title/description/selection/siteName/imageUrl/contentType`；文本依次限制为 240/800/2000/120 个字符，`contentType` 只能是 `article`、`video` 或 `podcast`。
- `source` 和 `follow-batch` 的候选项只保留 `url/name/externalId/imageUrl`；名称与外部 ID 分别限制为 120 和 80 个字符。`follow-batch` 只接受 `bilibili` 平台，三个候选数组分别不超过 500 项，`previousCount` 必须是 0–1,000,000 的安全整数。
- URL 必须是不超过 4096 个字符的 `http:` 或 `https:` 绝对地址，且不得包含用户名或密码。这一限制同时适用于扩展的采集/本地降级队列、桌面服务端以及 Web 应用的队列导入边界，不得依赖下游服务端才拒绝 URL userinfo。各边界去掉 URL fragment 及非根路径末尾的多余斜线；任何必填或已提供的可选 URL 无效时，整个队列项被拒绝。
- 所有未列出的顶层或嵌套字段（例如 `token`、`cookies`、请求头快照或任意嵌套对象）都必须丢弃，不得出现在响应、队列读取结果或持久化文件中。

## 数据映射

- 任意网页收藏映射为隐藏的系统来源“网页剪藏”下的一条 `article`、`video` 或 `podcast` 内容；隐藏来源不出现在订阅列表，也不进入“今日”，但内容可在稍后看、合集和搜索中出现。
- 同一规范 URL 已存在时不创建重复内容，只补充目标合集关系。
- 订阅候选必须经过 `/api/source-preview`，不得由扩展直接构造可自动刷新的 Feed。所有 Bilibili UP 主主页入口统一固定展示 RSSHub 对 `space.bilibili.com/{uid}` 标记为 Radar 可发现的 9 类来源：UP 主图文、UP 主投币视频、UP 主动态、UP 主粉丝、UP 主关注用户、UP 主点赞视频、用户追番列表、UP 主默认收藏夹、UP 主投稿。选项支持多选并合并为一个来源，默认只选择“UP 主投稿”；批量导入时同一组选项应用到本次所有 UP 主。普通添加订阅、浏览器助手单个来源、关注批量导入和来源设置重新选择均复用同一套固定选项。
- “UP 主粉丝”和“UP 主关注用户”依赖登录 UID 及自建 RSSHub 的 `BILIBILI_COOKIE_*` 配置；项目按现有 sidecar 约定把 Radar 候选补全为登录 UID `1`，对应 `BILIBILI_COOKIE_1`。缺少配置时允许选择，但导入会保留为待重试项。投币、点赞、追番和默认收藏夹还受目标用户的公开设置影响；UP 主投稿路由受较严格的反爬限制。频道视频、频道合集和非默认收藏夹还需要主页 URL 中不存在的 `sid` 或 `fid`，不能从一批 UP 主主页安全推导，因此不放入固定清单。
- 来源以规范化公开 URL 去重。批量加入时建立当前时间基线，预览到的历史条目不计入新增；批量导入默认不保留历史条目，避免污染“今日”。
- Bilibili 候选的公开昵称优先成为订阅源名称，公开头像 URL 写入来源的 `imageUrl`；应用使用圆角头像展示，图片不可用时回退到现有的名称首字色块。头像仅保存 URL，不下载图片二进制，也不进入扩展权限范围之外的请求。
- 捕获数据只包含公开页面元数据和用户主动选中的文字。第一版不保存完整正文或页面快照。

## 扩展界面

- 弹窗顶部显示当前页面标题、站点和识别状态。
- 默认显示自动连接状态，不要求配对码；高级连接设置保留本地应用地址和 Docker/网页模式配对码输入。
- 普通捕获按钮在成功入队后打开或聚焦本地应用。
- 扩展无原生激活通道时，`OUR_CHOICE_OPEN_APP` 只能表示“在浏览器标签页打开自选”，弹窗按钮、状态文案和返回字段都不得声称已启动或激活 Mac 原生应用。复用已记忆的 `appTabId` 前必须先读取标签并确认其当前 URL origin 精确等于当前 `appUrl`；标签已被关闭、ID 被复用、URL 不可读或 origin 不匹配时必须新建标签，不得导航无关页面。配置写入与 `appTabId` 更新必须串行化并以最新配置为基础，不得用旧快照覆盖新的地址或配对码。
- Bilibili 扫描区显示本轮累计数量、本页新增数量、开始/重新开始、扫描本页和完成并发送操作。
- 全部关注页面额外提供“自动扫描全部关注”；运行中显示进度并允许取消，普通页面不显示或禁用该操作。
- “完成并发送”成功后明确提示仍需在应用确认导入；若自动连接和网页模式配对都不可用，扫描状态和本轮候选保持不变。
- 无法访问的页面（浏览器内部页、扩展页或没有公开 HTTP(S) URL）显示明确错误，不创建队列项。
- 提供“导出待处理 JSON”作为通信不可用时的恢复路径；导出不包含配对码。

## 应用界面

- “订阅”页提供“浏览器助手”入口；原生应用设置显示自动连接说明和“检查待处理内容”，不要求生成配对码；普通网页模式仍提供生成、复制和撤销配对码的兼容入口。
- 收到队列后打开确认弹窗，分为网页收藏和来源候选，默认勾选可导入且不重复的项目。
- 用户确认后立即关闭导入确认弹窗，并创建一个独立于弹窗生命周期的后台导入任务；切换页面、收起进度窗口或关闭确认弹窗都不应中断任务。
- 右上角进度悬浮窗显示“已导入 / 全部”和据此计算的整数百分比，并分别显示成功导入、重复跳过和失败数量。这里的“已导入”表示已经完成导入判定的项目，因此重复跳过或失败也会推进总体进度。运行中可以收起为紧凑状态入口，之后再次展开；任务结束后可以关闭结果窗口。
- 运行中的任务支持暂停、继续与取消。暂停只阻止领取新的候选，允许已经发出的网络请求正常收尾；取消会中止仍在进行的请求、不再领取新候选，并保留已经成功完成的导入结果。被取消或失败的扩展队列组不做确认，后续仍可重试。
- 同一时间只运行一个浏览器助手导入任务；任务进行中不重复打开新的助手确认窗口，也不能启动第二个任务。
- 通过交接地址打开但原生会话/网页配对缺失、错误或扩展桥未响应时，应用自动打开浏览器助手设置并显示具体恢复提示，不允许静默停留在首页。
- 收藏区可统一选择“稍后看”或一个用户自建合集；来自“收藏到合集”的项目必须选择合集才能确认。
- 来源区显示平台、名称、URL、已订阅状态和 Bilibili 关注差异摘要。
- Bilibili 批量导入直接把由 MID 和固定内容范围生成的 Radar 选择标识交给首次预览请求，避免对每个账号重复执行一次“发现后再选择”；账号级任务限制为最多六路并发，单账号内部仍沿用服务端的范围级并发上限，避免无界请求压垮 RSSHub。非 Bilibili 来源保留“先发现、再选择”的兼容流程。
- 完成或取消后汇报收藏数、订阅数、重复数和失败数；进度分母以用户确认的收藏及来源候选总数为准，重复项也会作为已处理项推进进度。
- 导入任务必须先从最新的内存快照构造完整的 `next AppData`，并同步成功写入 `our-choice:state:v1`，然后才可向桌面队列或扩展队列发送 ACK。`localStorage.setItem` 抛错时不得发送 ACK、不得从页面待处理列表移除任何项，并必须向用户提示本地保存失败。普通的延后 React effect 落盘不能作为 ACK 前的成功证明。
- ACK 的粒度必须与扩展队列项一致：未勾选的 `clip` 不确认；未勾选的单条 `source` 不确认；`follow-batch` 只有在其全部候选都被勾选，且每个候选都已成功保存或判定为重复时才能整组确认。任一候选未勾选、失败、取消或尚未完成时都保留整个队列项供后续重试。

## 文件与兼容性

- 扩展源码位于 `browser-extension/`，不需要构建即可通过 Chromium 的“加载已解压的扩展程序”安装。
- Service Worker 与临时页面注入共享的辅助脚本必须使用标准 `.js` 扩展名；不得通过 `importScripts()` 加载 `.cjs`，因为 Chromium 会把扩展内 `.cjs` 作为 `application/octet-stream` 并拒绝注册 Service Worker。
- 首版目标为 Chrome/Edge Manifest V3；页面解析和数据契约保持浏览器 API 之外的纯函数，供 Node 测试验证。
- 应用仍可在没有扩展时独立运行，现有备份格式和 `our-choice:state:v1` 数据保持向后兼容。

## 验收标准

- Manifest 仅声明 `activeTab`、`scripting`、`storage`，通信桥只匹配两个本地应用来源。
- 扩展目录不包含被 Service Worker 引用的 `.cjs` 文件；`background.js` 和页面注入统一加载 `shared.js`，保证“加载已解压的扩展程序”可完成注册。
- 页面解析可以提取规范 URL、RSS/Atom、选中文字和 Bilibili MID，并过滤非 HTTP(S) 与重复候选。
- Bilibili 卡片解析可以提取并合并 MID、昵称与头像；订阅列表和来源详情显示头像并具备首字回退。
- 关注扫描可以合并多次本页结果并计算新增/不再出现差异；空扫描不能覆盖上一次完成快照。
- 自动全量扫描覆盖分页推进、同源导航恢复、重复页终止、超时/取消保留结果、末页自动发送，以及最多 200 页保护上限。
- 超过 500 个去重关注候选的扫描在发送前明确失败，不发起桌面投递、不写扩展队列、不结束或覆盖当前扫描快照。
- 应用可以接收、校验、预览和确认收藏、单来源订阅及 Bilibili 批量来源；重复项不重复创建。
- 确认导入后原弹窗立即关闭，右上角任务窗口按“已导入 / 全部”更新百分比；收起不终止任务，暂停不领取新项，继续恢复领取，取消会中止请求并保留已完成结果。
- Bilibili 批量来源首次请求携带固定范围选择，账号级并发不超过六路；非 Bilibili 来源仍可走发现范围兼容流程。
- 自动连接和网页配对都不可用时，发送操作保持扩展队列与关注扫描不变；连接成功后的交接会自动打开确认弹窗，失败时必须显示可操作的连接错误。
- 扩展降级 ACK 只在收到 requestId 匹配的成功回复后生效，超时或错误回复保留队列；应用本地持久化失败时不发送 ACK。
- 未勾选的收藏/来源和任一未完整处理的关注批次均保留在原队列；只有已完整处理并成功持久化的队列项才会被确认。
- 配对码与扩展队列不进入应用 JSON 备份；短期原生会话只可暂存在扩展自己的本地配置中，不进入产品数据、URL、日志或桌面状态文件。应用重启后扩展可自动取得并覆盖新值，旧会话不能继续调用桌面端点。
- 只有携带当次 WKWebView bootstrap secret 的请求可登记或撤销桌面配对；普通 loopback 浏览器页面的空/旧本地状态不得修改原生配对。
- Chrome 与 Safari adapter 都在复用标签前验证当前 origin，且并发的配置保存/打开页面不会用 stale merge 覆盖最新配对配置。
- 新增专项测试、现有测试、构建与 lint 全部通过；本机验证覆盖原生自动连接、应用重启后的 401 自动续连、打开助手确认界面和保存捕获内容，浏览器网页回退验证仍覆盖手工配对。
